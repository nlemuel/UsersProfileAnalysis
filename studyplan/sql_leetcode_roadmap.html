Os "Tipos de Problemas" do SQL

Assim como DFS/BFS em algoritmos, SQL tem padrões recorrentes. Aprenda a identificá-los pelo enunciado.

Fase 1

Agregação + Filtro de Grupo

Contar, somar, médias agrupadas. O padrão mais comum em análise de negócios.

GROUP BYHAVINGCOUNTSUMAVG
⚠ Armadilha: WHERE filtra linhas, HAVING filtra grupos — não são substituíveis.
Fase 2

JOINs

Combinar tabelas. INNER retorna interseção. LEFT retorna todos da esquerda + match da direita (NULL se não houver).

INNER JOINLEFT JOINSELF JOINCROSS JOIN
⚠ Armadilha: LEFT JOIN com WHERE na tabela direita vira INNER JOIN implicitamente.
Fase 3

Subqueries / CTE

Queries dentro de queries. CTE deixa legível. Correlated subquery referencia a query externa — cuidado com performance.

WITHASEXISTSINNOT IN
⚠ Armadilha: NOT IN com NULL retorna vazio — use NOT EXISTS ou IS NOT NULL.
Fase 4

Window Functions

Cálculos por janela sem colapsar linhas. ROW_NUMBER, RANK, LAG, LEAD, Running Total. O padrão mais poderoso do SQL analítico.

OVERPARTITION BYORDER BYROW_NUMBERLAG
⚠ Armadilha: RANK pula números, DENSE_RANK não — escolha conforme o requisito.
Fase 4

Top N por Grupo

"Os 3 produtos mais vendidos por categoria." Sinal claro: ranking + partição. Sempre ROW_NUMBER() OVER (PARTITION BY grupo ORDER BY métrica).

ROW_NUMBERPARTITION BYWHERE rn <= N
⚠ Armadilha: não dá para usar Window Function direto no WHERE — precisa de CTE ou subquery.
Fase 5

Gaps and Islands

Detectar sequências consecutivas ou lacunas. Clássico em análise de eventos, sessões, streaks de usuários.

ROW_NUMBERLAGGROUP BY island
⚠ Sinal: "dias consecutivos", "sequência ininterrupta", "lacunas entre eventos".
Fase 6

Retenção / Cohort

Agrupar usuários pela data de entrada (cohort) e medir retenção nos meses seguintes. Base de analytics engineering.

DATE_TRUNCMIN(data)DATEDIFFCASE WHEN
⚠ Sinal: "% de usuários que voltaram", "mês 0, mês 1, mês 2..."
Fase 7

Analytics Engineering / SCD

Slowly Changing Dimensions, Feature Store, snapshots temporais. Sua tabela feature_store_cliente já segue esse padrão.

dtRefvalid_fromvalid_tosnapshot
⚠ Sinal: "estado do cliente em uma data específica", "evolução temporal de features".

1. Top 5 Produtos por Receita Fácil GROUP BY
Contexto: você é analista da plataforma de rewards. O time de produto quer saber quais produtos geram mais receita.
Liste os 5 produtos com maior receita total (soma de vlProduto × QtdeProduto), mostrando o nome do produto, categoria e receita total. Ordene do maior para o menor.
Tabelas: transacao_produto produtos
💡 Hints (clique para revelar)
  • Hint 1: Você precisa combinar transacao_produto com produtos para ter o nome. Que tipo de JOIN usar?
  • Hint 2: A receita por linha é vlProduto * QtdeProduto. Você precisa somar isso agrupando por produto.
  • Hint 3: Use LIMIT 5 no final. Lembre de fazer ORDER BY DESC para ordenar do maior.
✅ Solução comentada 
-- Padrão: GROUP BY + JOIN + ORDER BY + LIMIT
SELECT
    p.DescNomeProduto,
    p.DescCategoriaProduto,
    -- Receita total: preço × quantidade
    SUM(tp.vlProduto * tp.QtdeProduto) AS receita_total
FROM transacao_produto tp
INNER JOIN produtos p ON tp.IdProduto = p.IdProduto
GROUP BY
    p.DescNomeProduto,
    p.DescCategoriaProduto
ORDER BY receita_total DESC
LIMIT 5;
🧠 Sinais para reconhecer no futuro
📌"Top N de X" → ORDER BY DESC + LIMIT N
📌"maior receita total" → SUM() + GROUP BY
📌Sempre que precisar de nome/desc de outra tabela → JOIN
2. Clientes Ativos por Canal de Origem Fácil GROUP BY + HAVING
O time de growth quer entender a distribuição de clientes por canal e focar nos canais com mais engajamento.
Para cada canal de origem (DescSistemaOrigem), mostre: número de clientes únicos, total de transações, e média de pontos por transação. Filtre apenas canais com mais de 1.000 clientes únicos.
Tabelas: transacoes
💡 Hints
  • Hint 1: COUNT(DISTINCT IdCliente) conta clientes únicos — diferente de COUNT(*).
  • Hint 2: O filtro "mais de 1.000 clientes" é sobre o resultado do GROUP — use HAVING, não WHERE.
✅ Solução 
SELECT
    DescSistemaOrigem,
    COUNT(DISTINCT IdCliente)  AS clientes_unicos,
    COUNT(*)                        AS total_transacoes,
    AVG(QtdePontos)                 AS media_pontos
FROM transacoes
GROUP BY DescSistemaOrigem
HAVING COUNT(DISTINCT IdCliente) > 1000
ORDER BY clientes_unicos DESC;
3. Evolução Mensal de Transações com Variação Médio Window Function: LAG
O time de produto quer monitorar crescimento mês a mês. Você precisa mostrar não só o volume, mas a variação percentual.
Para cada mês (2024 e 2025), mostre: total de transações, total de pontos movimentados, e a variação percentual de transações em relação ao mês anterior. Ordene por data.
Tabelas: transacoes
💡 Hints
  • Hint 1: Em SQLite, use strftime('%Y-%m', DtCriacao) para extrair ano-mês.
  • Hint 2: LAG(coluna, 1) OVER (ORDER BY mes) pega o valor do mês anterior.
  • Hint 3: Você não pode usar LAG direto no SELECT com GROUP BY. Use CTE: primeiro agrupe, depois aplique a window function.
✅ Solução 
WITH base AS (
    SELECT
        strftime('%Y-%m', DtCriacao) AS mes,
        COUNT(*)            AS total_transacoes,
        SUM(QtdePontos)     AS total_pontos
    FROM transacoes
    GROUP BY mes
)
SELECT
    mes,
    total_transacoes,
    total_pontos,
    LAG(total_transacoes, 1) OVER (ORDER BY mes) AS transacoes_mes_ant,
    -- Variação %: (atual - anterior) / anterior * 100
    ROUND(
        (total_transacoes - LAG(total_transacoes,1) OVER (ORDER BY mes))
        * 100.0
        / LAG(total_transacoes,1) OVER (ORDER BY mes),
    1) AS variacao_pct
FROM base
ORDER BY mes;
🧠 Sinais para reconhecer
📌"variação em relação ao período anterior" → LAG()
📌"crescimento mês a mês" → LAG + divisão percentual
📌Window Function depois de GROUP BY → sempre use CTE
4. Top 1 Produto por Categoria Médio Top N por Grupo
O time de catálogo quer saber, em cada categoria de produto, qual é o campeão de vendas.
Para cada categoria de produto, mostre o produto com maior número de vendas (maior QtdeProduto total). Em caso de empate, mostre o que vem primeiro alfabeticamente.
Tabelas: transacao_produto produtos
💡 Hints
  • Hint 1: Esse é o clássico "Top N por Grupo". Sinal: "o melhor de cada categoria".
  • Hint 2: Use ROW_NUMBER() OVER (PARTITION BY categoria ORDER BY vendas DESC) para numerar dentro de cada grupo.
  • Hint 3: Filtre WHERE rn = 1 fora do CTE — window functions não podem estar no WHERE.
✅ Solução 
WITH vendas_produto AS (
    SELECT
        p.DescCategoriaProduto,
        p.DescNomeProduto,
        SUM(tp.QtdeProduto) AS total_vendas
    FROM transacao_produto tp
    INNER JOIN produtos p ON tp.IdProduto = p.IdProduto
    GROUP BY p.DescCategoriaProduto, p.DescNomeProduto
),
ranking AS (
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY DescCategoriaProduto
            ORDER BY total_vendas DESC, DescNomeProduto
        ) AS rn
    FROM vendas_produto
)
SELECT
    DescCategoriaProduto,
    DescNomeProduto,
    total_vendas
FROM ranking
WHERE rn = 1
ORDER BY DescCategoriaProduto;
5. Retenção Mensal de Clientes (Cohort) Difícil Cohort Analysis
O time de produto precisa de uma análise de retenção: dos clientes que começaram em cada mês, quantos voltaram nos meses seguintes?
Calcule a retenção por cohort mensal. Para cada cohort (mês da primeira transação do cliente), mostre quantos clientes estão no cohort e a % que voltou a transacionar em cada um dos meses seguintes (mês 0, 1, 2, 3...).
Tabelas: transacoes
💡 Hints
  • Hint 1: Sinal claro de cohort: "primeiro mês do cliente". Comece com MIN(DtCriacao) por cliente.
  • Hint 2: Use CAST((julianday(mes_transacao) - julianday(cohort)) / 30 AS INT) para calcular o período relativo em SQLite.
  • Hint 3: Monte em 3 CTEs: (1) cohort de cada cliente, (2) transações por cohort+período, (3) cálculo do %.
✅ Solução 
WITH cohort_cliente AS (
    -- Mês de entrada de cada cliente
    SELECT
        IdCliente,
        strftime('%Y-%m', MIN(DtCriacao)) AS cohort
    FROM transacoes
    GROUP BY IdCliente
),
atividade AS (
    -- Junta cada transação com o cohort do cliente
    SELECT
        cc.cohort,
        cc.IdCliente,
        strftime('%Y-%m', t.DtCriacao) AS mes_ativo,
        CAST(
          (julianday(strftime('%Y-%m-01', t.DtCriacao))
         - julianday(cc.cohort || '-01')) / 30
        AS INT) AS periodo
    FROM transacoes t
    INNER JOIN cohort_cliente cc ON t.IdCliente = cc.IdCliente
),
tamanho_cohort AS (
    SELECT cohort, COUNT(DISTINCT IdCliente) AS total_cohort
    FROM cohort_cliente
    GROUP BY cohort
)
SELECT
    a.cohort,
    tc.total_cohort,
    a.periodo,
    COUNT(DISTINCT a.IdCliente) AS clientes_ativos,
    ROUND(
        COUNT(DISTINCT a.IdCliente) * 100.0
        / tc.total_cohort, 1
    ) AS retencao_pct
FROM atividade a
INNER JOIN tamanho_cohort tc ON a.cohort = tc.cohort
GROUP BY a.cohort, tc.total_cohort, a.periodo
ORDER BY a.cohort, a.periodo;
